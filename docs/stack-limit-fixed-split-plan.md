# 固定 999 堆叠格式实施方案

## 目标

将物品数量统一存储在物品 `+0x10` 的 `bit22..31`（10 bit），最大值 999。该布局在进程生命周期内固定，不使用格式标记，不扫描背包迁移，不因配置切换改写存档数据。

## 位域边界

| 范围 | 语义 | 约束 |
|---|---|---|
| `bit0..7` | 混沌等级 | 保持原版 |
| `bit8..15` | 混沌率 | 保持原版 |
| `bit18..23` | 宝石属性 ID | 仅宝石对象使用；宝石不可堆叠，不进入数量写路径 |
| `bit22..31` | canonical 数量 | 仅可堆叠物品使用，`1..999` |
| 背包对象 `+0x10 bit0..24` | 背包容量 | 与物品对象分离；实际容量为 4/8/12/16 |

存档子物品检查永久读取 `bit0..21`，避免数量高位被误判为子物品数量。

## 实现策略

1. 保留现有 31 个数量位段 patch 和 2 个存档检查 patch，启动时一次性应用；它们构成固定 canonical 布局。
2. 将 9 个 `99→999` clamp patch 独立为可逆集合。配置只切换这 9 个 clamp：
   - 开启：新建、合并、存入等路径上限为 999；
   - 关闭：新操作上限为 99；
   - 两种状态都继续使用 `bit22..31` 读取/写入；已有 100..999 不迁移、不截断，仍可正确读档和操作。
3. 删除 `data_op_migrate_stack`、后台迁移线程和关闭时回写旧格式的逻辑。
4. `data_op_add_item` 根据配置选择 99/999 clamp，但始终写 canonical `count << 22`。
5. 不引入 inline hook 或 utility-level hook；所有游戏路径继续使用已反汇编验证的 42 个调用点 patch。

## 变更范围

- Native patch：`game_patch.cpp/.h`、`game_access.cpp`。
- Native codec：新增 `stack_codec.h`，供生产代码和 host 单测共同使用。
- Native API：`game_inventory.cpp` 使用 codec 和配置上限。
- Host 测试：`tests/test_host.cpp`、`tests/CMakeLists.txt`，覆盖边界值及低位字段保留。
- 文档：`game_symbols.h`、`docs/api-reference.md`、`architecture.md` 同步 canonical 语义。

## 不变条件

- 装备、宝石、容器类物品不得进入普通堆叠数量写入路径；既有 `item_is_equip`/原版可堆叠判断继续作为边界。
- `bit0..21` 之外的字段不得被 codec 清除；codec 只清写 `bit22..31`。
- patch 失败必须保持已有回滚行为，并记录错误；不能在部分 patch 状态下继续运行。

## 验证顺序

1. Host 单测：`0、1、99、100、127、128、999`，超范围 clamp，低 22 位保留，装备 sentinel 不变。
2. Native 编译：LSP diagnostics、Gradle debug build。
3. 静态检查：确认迁移符号、旧 bit25..31 注释和配置回滚路径已清除。
4. 真机：新建/拾取/合并/拆分/使用/出售/商店/合成/掉落/拆包/存档重启。
5. 隔离验证：装备、宝石、箱子/封印物、任务物品，以及已有 100..999 堆叠在配置开关前后的读写一致性。

## 发布边界

本分支先完成实现和构建验证，不递增版本号、不生成正式 release。版本递增和真机验收通过后，按项目规则单独提交版本提交。
